MODEM (verificato sul device, nessuna SIM, test mode adb)
- AT su /dev/smd7 (nessun processo lo tiene aperto; i daemon hanno solo /dev/diag). Comandi BroadMobi nel fw modem (strings mtd7_qdsp): +BMBANDPREF, +BMBANDLOCK (?: 0, range 0-2, legato a NV_BMT_LTE_BAND_LOCK_I, non usato), +BMSYSINFO (maschere troncate a 32 bit), +BMCELLINFO/+BMTCELLINFO/+BMLOCKCELL (? e =? → ERROR), $QCBANDPREF (ERROR).
- AT+BMBANDPREF? → "+BMBANDPREF: 0x<gw>, 0x<lte>, 0x<tds>"; =? → "+BMBANDPREF: support band: 0x<gw>, 0x<lte>, 0x<tds> ". Valori del device: gw 0x2000000400380 (GSM 900/1800 + WCDMA B1/B8), lte 0xA0000800C5 = capacità (B1 B3 B7 B8 B20 B38 B40; bit n = banda n+1), tds 0x3F con capacità 0x0.
- SCRITTURA: AT+BMBANDPREF=<gw>,<lte>,<tds> in ESADECIMALE SENZA 0x. Con "0x..." il parser legge 0,0,0 → OK senza alcun effetto (trappola: un no-op con 0x sembra funzionare). Ogni maschera deve stare nella capacità (pref & cap) altrimenti ERROR ("band value is out of range"): tds 3F → ERROR. tds 0 (e in generale 0) = invariata. Comando usato: AT+BMBANDPREF=<gw letto senza 0x>,<lte hex>,0. Ripristino originale: 2000000400380,A0000800C5,0.
- Effetto immediato (rilettura) e PERSISTENTE: aggiorna l'item EFS /nv/item_files/modem/mmode/lte_bandpref (8 byte LE; letto via DIAG: 0x44 dopo blocco B3+B7, poi di nuovo c5000800a0000000). Reset di fabbrica (bm_reset*.sh) non tocca le bande; "Cellulare preferito" stock (NAS_Client::SetModePref, libqcmap_client.so.1 74f1ad80…) manda QMI 0x33 con solo mode_pref valido → bande invariate.
- API nativa qcmap_fcgi set_current_network_band_pref (codici 3/7/20/0, "auto" = 0x80044 senza B1/B8/B38/B40) NON usata.
- Diagnosi fatta con F3 via DIAG (tools/dwr_diag_f3_capture.ps1): dsatcmdp "Command Name +BMBANDPREF", dsatext.c:4038 valori parsati, dsatext.c:4082 out of range, dsatext.c:1131 cmd_err del CM. Note in analysis/notes/device-diag-f3-bandpref*-0111.txt.

CARRIER AGGREGATION (conclusione: nessun interruttore; non disattivata)
- Nessun comando AT né QMI NAS per CA nel fw (lista qmi_nasi_* senza cphy_ca/ca_info) → stato CA NON osservabile dal router.
- EFS letti via DIAG (sola lettura): /nv/item_files/modem/lte/common/ca_disable ASSENTE, lte_category assente, rrc/cap/disable_ca_bandwidth_combo e disable_ca_intra_band_validation assenti, fgi/fgi_rel9/fgi_r10, lte_rrc_release_ver, lte_3gpp_release_ver, band_priority_list, mcc_band_restriction_list, pci_lock assenti → default del firmware. Che il default sia "CA abilitata" è INFERENZA (non decompilato: codice Hexagon). Fw modem contiene codice SCC/CA (lte_LL1_scell_db, LTE_ML1_DLM_CA_SCC_*) e schede RF *_ca_* (es. rfc_wtr1625_qfe2720_ca_eu); scheda RF del device ignota.
- Effetto del blocco: con una sola banda nessuna CA tra bande diverse; la UI lo dice. Possibile solo scrivere ca_disable=0 esplicito via DIAG dal PC (non fatto, non richiesto).
- NV letti via DIAG NV_READ (tools/dwr_diag_efs_read.ps1 -Nv, sola lettura; note device-rf-hwinfo-0111.txt): 1878 RF_HW_CONFIG = 0x2E (46), 1877 = 0x0002000000400380 (bande GW), 6828 = 0xA0000800C5 (bande LTE = capacità), 65633 stato 6 (non valido). AT$QCHWREV → Part=149 version=2.1. Scheda RF 46 NON mappata a un nome: le rfc_* nel fw sono classi C++ (nomi RTTI tipo "26rfc_wtr1625_apac_ca_cmn_ag", nessuna tabella dati ID→nome; la scelta è nel codice Hexagon); ricerca web senza elenco pubblico dei valori.
- Verifica della CA possibile SOLO con SIM registrata: stringa F3 "Activate secondary carrier  FirstCmeBpg %d LastCmeBpg %d" (+ UMID LTE_ML1_DLM_CA_SCC_ACT_IND) → filtrare con dwr_diag_f3_capture.ps1 -Match 'secondary carrier|scc|scell'. DIAG serve mentre il modem è registrato: test mode (se registra: da verificare, la nota "test mode non registra" non è provata con SIM) oppure, in modo normale, il ponte diag_socket_log → PC con IP 192.168.0.10 in ascolto su TCP 2500. Cat4 = 150 Mb/s max anche con CA (2×10 MHz): guadagno solo con portanti strette (10-15 MHz).

DIAG DAL PC (porta "Qualcomm HS-USB Diagnostics 9025" = COM10 in test mode; Python 3.15 sul PC senza pyserial → PowerShell SerialPort)
- tools/dwr_diag_efs_read.ps1 [-Paths a,b] = EFS2 HELLO/STAT/GET/OPEN O_RDONLY/READ/CLOSE (sottosistema 0x4B 0x13), solo lettura. GET (26) risponde corto (4b131a00 + errno 2) → fallback OPEN/READ funziona anche sugli item file (mode 0160777). Valori >2^31 in PowerShell: usare 4294967295, non 0xFFFFFFFF (= -1); Write-Host dentro le funzioni (Write-Output finisce nel valore restituito); con -File i percorsi arrivano come un'unica stringa con virgole.
- tools/dwr_diag_f3_capture.ps1 -Adb "<argomenti adb>" = maschere F3 runtime (0x7D sub 5) a 0x1F per N s, stampa 0x79 filtrati, poi maschere a 0. Messaggi 0x79 con stringhe in chiaro (fmt + file); 0x92 (QSR) non decodificati.
